# 架构说明

`cloud-native-security-resource-control-policies` 提供一套**组织级资源控制策略（RCP）参考库**：把大规模云环境中的「资源访问边界」以可审计的 Deny 策略表达，覆盖数据外边界、组织内边界、访问模式、可信身份提供方与关键服务基线。适用于需要统一治理与合规控制的多账号/多项目环境。

## 治理层级

       │             │             │             │             │

 ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
 │    01    │  │    02    │  │    03    │  │    04    │  │    05    │
 │   DATA   │  │INTRA-ORG │  │  ACCESS  │  │ TRUSTED  │  │ SERVICE  │

 └─────┬────┘  └─────┬────┘  └─────┬────┘  └─────┬────┘  └─────┬────┘

## 核心组件

| 目录 | 说明 |
|---|---|
| `00-policy-format.md` | IAM 5.0 策略 JSON 骨架 + 条件键速查 |
| `01-data-perimeter-guardrails/` | 可信身份 / 可信资源 / 可信网络边界（Deny） |
| `02-intra-organization-boundaries/` | 组织单元间访问限制 |
| `03-resource-access-patterns/` | 仅 HTTPS / 服务主体访问限制 |
| `04-oidc-identity-providers/` | 可信外部身份提供方（OIDC IdP）白名单 |
| `05-service-specific-controls/` | OBS / DEW(KMS) / IAM 等关键服务基线 |

## 设计说明

- 全部为 Deny 型粗粒度预防控制（不授权，与身份/资源策略求交集生效）
- 落地原则：策略 JSON 只使用官方授权项与条件键；无法直接表达的控制落到服务原生安全配置，见各分类 README 的「服务侧替代」小节
- 策略为参考模板，使用前需删除 `_hc_note` 说明字段、替换全部 `<...>` 占位并充分测试（建议先在非生产项目/组织单元验证）
